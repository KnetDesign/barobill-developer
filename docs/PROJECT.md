# PROJECT — 2026 바로빌 개발자센터 리뉴얼

## 개요 (확정)
- 운영사 케이넷(KNET, 2002 설립) · 바로빌(BAROBILL, 2009 시작) — 전자문서·세무·금융 데이터·메시징 B2B API.
- 고객: 기업 내부 개발팀, ERP·SaaS·SI 개발사, 솔루션 파트너. 고객 규모 수치(약 20만/25만)는 외부 게시 전 공식 수치 확인.
- 기존 SOAP·함수 호출 방식(Delphi·VB·PowerBuilder·ASP·ERP/SI 강점) 유지 + REST 신규 추가.

## 범위
- 포함: REST API 추가(확정, 재논의 금지) · SOAP 병행 · 포털 리뉴얼 · 상품 소개 · 문서 체계/탐색 · 가입·온보딩 · 직접 고객/리셀 파트너 경로 구분 · 반응형 · 디자인 시스템.
- 차기 분리: 인증키 자동 발급 고도화 · 샌드박스 고도화 · SDK 신규 구축 (UI는 확장 가능하게만).

## 사용자 (초기 페르소나, 실데이터 검증 필요)
A 개발자(빠른 연동·명확한 문서·오류 해결) · B 의사결정자(비용·안정성·예측 가능성) · C ERP·SaaS·SI·파트너(재판매·정산·기술 지원).

## 전환 모델
- 직접 고객: 방문 → 이해 → 가입 → API 테스트 → 연동 → 결제·운영
- 리셀 파트너: 방문 → 파트너 서비스 이해 → 가입 → 사업자등록증·정산 담당자 → 승인 → 리셀 매출
- 일반 고객이 파트너 등록을 필수로 오해하지 않게. (주의: 화면설계서 카피는 "파트너 등록 → 인증키" 표현을 씀 — 실제 정책 확인 필요, DECISIONS 참조)

## KPI
North Star: 리뉴얼 유입 → 결제 신규 고객 수·매출. 선행: 가입→첫 테스트 성공 시간, 테스트→결제 전환, 파트너 등록 완료율. 가드레일: SOAP 무중단, 연동 CS 증가 방지, 문서 정확성. 측정 데이터 없이 개선 효과를 주장하지 않는다.

## 전략 (합의)
- 핵심: **도입·연동 편의성**. 1단계 시작 장벽(이해·탐색·가입·테스트) → 2단계 연동 경험(문서·REST/SOAP 구분·예제·오류 자가 해결·AI 도구 지원).
- REST는 입장권이지 차별화가 아님. 고객 가치 = 쉽고 빠르게 시작하고 안정적으로 연동.
- 경쟁: 팝빌·볼타(직접), 스마트빌 / 데이터 참고 CODEF·쿠콘·데이터허브(정면 경쟁 지양) / DX 참고 포트원·토스페이먼츠·Stripe·Twilio / 가격 표현 참고 Baremetrics.
- 발행 고객이 카드·계좌·홈택스 등 데이터 API로 자연 확장 — 발행→수집 연결은 보조 가치.
- 폐기: 자체 엔진 여부를 선택 기준으로 · 내부 구조 우선 포지셔닝 · API 범위만 강조 · REST 자체를 핵심 차별화로.
- 내부 참고 데이터(문의 비중, 설문 등)는 원본 미검증 → 내부 판단용, 외부 문구 사용 금지.
- 요금: 구체 단가 비공개(리셀 충돌). 과금 구조·이용 방식·VAT·견적 절차 중심.

## 브랜드·카피
검증된 서비스 · 신뢰 · 쉬운 시작 · 개발자 친화 · 비즈니스 확장. 메인 H1 확정: "기술의 연결, / 더 큰 비즈니스 가치"(2026-11-27). 나머지 카피는 화면설계서 기준 (제안) 상태.
