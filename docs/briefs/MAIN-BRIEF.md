# 메인 디자인 브리프

## 한 줄 목적
3초 안에 "기업 업무·데이터를 잇는 API이고, 테스트를 바로 시작할 수 있다"를 전달 → 모든 섹션이 '테스트 시작하기'로 수렴.

## 흐름 (섹션 제목만 읽어도 이야기가 돼야 함)
무엇을 하는 곳인가(01) → 왜 바로빌인가(02~02-3) → 어떻게 시작하나(02-4) → 어떤 업무에 쓰나(03) → 누가 쓰나(04) → 남은 의문(05) → 시작(06)

## 섹션별 의도 · 꼭 지킬 것
| 섹션 | 의도 | 꼭 지킬 것 | 열려 있음(디자인 재량) |
|---|---|---|---|
| 01 Hero · 다크 | 정체성 + 즉시 행동 | H1 2줄 확정 "기술의 연결, / 더 큰 비즈니스 가치" · 리드에 API 이름 · CTA 2개(테스트 시작하기 > 견적 문의) · 첫 화면 800 안에 히어로+고객 로고 | 가운데 정렬 vs 6:6+도식, 배경·그래픽 |
| 02 WHY | 선택 이유 3개를 한눈에 | 운영 안정성 / 연동 편의성 / 비용 경쟁력 순서 · 카드 클릭 → 02-1~3 이동 · 숫자·근거는 '보여주기' | 카드 시각물 표현 |
| 02-1 운영 안정성 · 다크 | "연동 후 운영은 바로빌이" | 근거 4개(AWS 서울 리전·트래픽 분산·실시간 모니터링·자동 백업) · 내부 장비명 노출 금지 | 도식 vs 숫자 칸 |
| 02-2 연동 편의성 | AI·문서·지원으로 막힘없음 | 아코디언 3항목(MCP는 미확정) · 'API 개발 문서 보기' 링크 | 문서 화면+터미널 vs 그래픽 칸 |
| 02-3 비용 경쟁력 | 도입비 0원·종량제 | **구체 단가 노출 금지** · 단가는 '파트너 등록 후 콘솔에서' | 시각물(미정) |
| 02-4 시작 절차 · 연한 면 | 3단계면 끝 | 정적 Stepper(진행 상태 표현 없음) · CTA 1개 | — |
| 03 상황별 솔루션 | 내 업무에서 찾기 | 2묶음 × 3카드 · 카드 전체가 링크 | 아이콘 유무 |
| 04 고객 사례 | 실제 고객의 말 | 스톡 인물 사진 금지 · 고객사 실명·로고 재동의 전 | 피처+카드 vs 큰 인용+탭 |
| 05 FAQ | 비용·테스트 의문 해소 | 아코디언, 첫 항목 열림 | — |
| 06 하단 CTA · 다크 | 마지막 행동 | 버튼 3개 같은 크기(시작·문의·소개자료) | 배경 패턴 |

## 확정 vs 미확정
- 확정: H1, 섹션 순서, GNB 메가메뉴 A안, 상품 13개 구성
- 미확정(디자인 결정): 히어로 레이아웃, 02-1~02-3 표현, 04 레이아웃, **브랜드 블루**, 그래픽 스타일
- 미확정(사업 확인): 고객 로고 게재 동의, 93.3%·25만·18개 언어 등 수치, 0원 항목 범위

## 디렉터 의견
- 화면설계는 '정보는 완성, 인상은 백지' 상태. 브랜드다움은 히어로 그래픽과 다크 섹션 2곳(01·02-1)이 결정 → 여기에 디자인 에너지 집중 권장.
- Concept 페이지의 로고 심볼(캡슐·노드·흐름선) 모티프를 히어로·02-1·06에 일관 적용하면 섹션 간 통일감 확보.
- 02-1~02-3은 같은 7:5 구조가 3번 반복 → 리듬 단조로움 위험. 다크/라이트 교차 외에 시각물 성격을 다르게(도식/화면/데이터) 가져가야 함.
